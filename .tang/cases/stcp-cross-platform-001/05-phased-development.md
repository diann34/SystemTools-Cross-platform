## 0. 执行总则

本期交付新插件 `SystemTools-Cross-platform`，与原 `SystemTools` 三平台并存。新插件纳入 A+B 档，C 档 46 项继续留在原插件；目标为 Windows、Linux（X11）和 macOS 均可构建运行。阶段按风险和依赖顺序推进，任一阶段的静态门禁、构建门禁或可重放证据不通过时，不得进入依赖该证据的后续阶段。

阶段合同中的"变更表面"指出工程区域和需核对的既有文件；具体实现由获批后的部门执行计划约束。阶段证据应记录命令、版本/TFM、文件清单、关键输出和失败原因，且落在本案 `.tang/cases/stcp-cross-platform-001/` 下。

# 阶段 0：工程脚手架与范围基线

## 0.1 目标

1. 以 U3 指定的 `E:\ClassIsland-git-misha` misha/v2 本地检出为 API 基线，建立宿主 `CrossPlatformProps` 模式下的 Windows、Linux/X11、macOS 三平台 TFM 构建入口。
2. 建立新插件独立工程与配置边界，不改变原 `SystemTools` 的工程、功能注册、配置或发布行为。
3. 按 R-5 裁剪本期不应进入新插件的 Windows/原生依赖：移除 `CsWin32`、`System.Management`、`System.Speech`、`DlibDotNet`、`OpenCvSharp4*`（含 Windows runtime）；保留 `ClassIsland.PluginSdk`、DI 依赖和 `FluentAvalonia` 所需能力。
4. 固化独立 manifest：独立 `id` 与功能命名空间、三平台 `supportedOSPlatforms`、随 U3 基线的 `apiVersion`，并建立全新配置命名空间。
5. 对照源插件行动目录完成 62 个行动文件到 61 个活动功能项的基线映射：`ClickSimulationAction.cs` 整文件注释、未编译且未注册，作为 1 个死代码文件注记而不计功能项。该基线必须与 A15+B14+C32 及总计 A33+B19+C46 对齐。

## 0.2 入口条件与依赖

- `04-spec.md` 已通过并作为本期规范性验收契约；其中 S3 R-1～R-10 与 U3/U4/U5 的用户决定不可在执行阶段推翻。
- 可访问源插件 `E:\My Github Projects\SystemTools`、宿主基线 `E:\ClassIsland-git-misha`，并能读取其工程/manifest/功能目录。
- 已有 01–04 工件中的范围、分类、禁用符号集合、计数口径和回滚原则可供复核。
- 阶段 0 不依赖 A/B 功能已经抽取；其出口产物是后续抽取与适配阶段所需的工程、依赖和计数基线。

## 0.3 变更表面

| 工程区域 | 需建立或核对的表面 | 约束 |
| --- | --- | --- |
| 新插件工程 | 新插件项目/解决方案及宿主 `CrossPlatformProps` 接入 | 三平台 TFM 与宿主检出 API 一致；不复制原插件的 Windows-only 工程属性 |
| 项目依赖 | 项目包引用、传递依赖和运行时资产 | 移除 S4.2 对应的 Windows 原生包；保留 PluginSdk、DI、FluentAvalonia；不携带 VoskWorker、C 档原生认证/视觉运行时 |
| 插件元数据 | 新插件 `manifest.yml`（参照源 `manifest.yml` 的 schema） | `id` 不得为 `SystemTools`；功能 ID/配置采用独立前缀；`supportedOSPlatforms` 覆盖 Windows、Linux、macOS；`apiVersion` 以 U3 基线为准 |
| 源功能清单 | 源 `Actions\*.cs` 及主题、组件、规则、触发器、服务、设置页目录 | 只建立可追溯范围基线，不在本阶段迁移 C 档源码或实现 A/B 行为 |
| 计数映射 | 62 文件→61 活动项映射及 A/B/C 汇总 | 去重同一代码实体；保留死代码注记；映射无重复、无遗漏，数字与 S4.1 一致 |
| 证据与记录 | 阶段 0 构建、包图、manifest、映射和门禁输出 | 所有 `.tang` 证据写入本案目录，供后续阶段和 S5 重放 |

## 0.4 边界与禁止事项

- 本阶段只建立脚手架、依赖裁剪、元数据/配置边界和范围基线；不开始 A 档逐文件抽取，不开始 B 档替换，不实现电源、窗口、文件夹递归、主题/遮挡/内存等功能。
- C 档 46 项不进入新插件；尤其不引入语音链路、屏幕截图、系统音量、输入注入、全局钩子、WMI、Windows 认证、摄像头原生运行时或系统级内存清理。
- 不修改原 `SystemTools` 源码、工程、manifest、配置或发布产物；不改变已审批的三平台并存、独立 ID、U3、U4、U5 决定。
- 不将本合同细化为函数体、精确补丁、逐文件实现顺序或部门分工；部门派工由后续批准后的 `tang_plan_ministries` 逐阶段产生。

## 0.5 验证与出口证据

阶段 0 必须形成可独立检查的证据包，至少包含以下结果：

1. **三平台 TFM 构建基线**：使用新插件解决方案的标准 Release 构建命令（`dotnet build <new-plugin-solution> -c Release`，按宿主 `CrossPlatformProps` 展开目标）验证 Windows、Linux/X11、macOS 三平台目标均被解析并成功构建；记录 SDK、宿主检出版本、实际 TFM 和每个目标的成功输出。任一目标未解析、仅恢复未编译或出现平台限定错误，阶段不通过。
2. **包裁剪与资产核对**：通过项目包清单/依赖图（如 `dotnet list <new-plugin-project> package` 及等价资产检查）确认禁用包及其 Windows runtime 资产不再进入新插件，确认 `ClassIsland.PluginSdk`、DI 和 `FluentAvalonia` 依赖可解析；VoskWorker 和 C 档原生运行时不在输出资产中。
3. **manifest 与配置独立性**：按宿主 manifest schema 解析新 manifest，证明 `id`、功能 ID 前缀和配置命名空间均不与原插件相同，三平台列表完整，`apiVersion` 与 U3 API 基线一致；输出解析结果及源 `manifest.yml` 对照记录。
4. **范围映射核对**：对源 `Actions` 目录实测 62 个 `.cs` 文件，明确 `ClickSimulationAction.cs` 为整文件注释死代码，得到 61 个活动功能项；映射表无重复/遗漏，行动分档为 A15+B14+C32，逐域合计为 A33+B19+C46=98，并记录与 `04-spec.md` S4.1 的一致性。
5. **原插件隔离检查**：对比阶段前后原 `SystemTools` 工程/manifest/配置或使用版本控制差异，证明没有被修改；新插件可独立禁用/卸载而不要求原插件改变。

阶段 0 只有在以上证据齐全、失败项为零且结果可被另一复核方重放时，才能标记为 `passed` 并解锁阶段 1。

## 0.6 风险检查点

| 检查点 | 风险 | 通过条件 | 失败处理 |
| --- | --- | --- | --- |
| CP-0.1 | 宿主 U3 基线的 TFM、SDK 或平台 props 不兼容 | 三平台目标均可解析，PluginSdk/Platforms.Abstractions 来自指定检出且版本记录完整 | 停止阶段推进，核对宿主基线与工程入口；不得用未经审批的发布包替代 |
| CP-0.2 | 包裁剪后仍由传递依赖带入 Windows 原生资产 | 依赖图和输出资产均无 S4.2 禁用包/运行时；保留包可解析 | 退回依赖边界修订并重新执行包图门禁，不进入源码抽取 |
| CP-0.3 | manifest/schema 或独立命名空间与并存策略冲突 | 宿主 schema 解析通过，ID/配置/功能前缀独立，三平台字段正确 | 修正元数据边界后重跑解析和隔离检查 |
| CP-0.4 | 行动文件、死代码或去重口径漂移 | 62→61 映射和 98 项汇总与 S4.1 完全一致 | 以源码和 `04-spec.md` 为准修订映射证据；计数未闭合不得进入阶段 1 |
| CP-0.5 | 脚手架意外改动原插件 | 原插件差异为空或有明确非本阶段外部变更说明 | 立即停止，保留现场和证据，隔离/撤销仅本阶段产生的误改后再复核；不得覆盖用户既有改动 |

## 0.7 回滚

阶段 0 的回滚边界仅限新插件脚手架、依赖声明、manifest/config 命名空间和阶段证据。若入口、包图、元数据或映射门禁失败，可整体禁用或移除新插件脚手架并保留原 `SystemTools` 不变；不得通过修改原插件来规避失败。回滚后保留失败输出与审计记录，修订阶段合同或输入后重新执行阶段 0。阶段 0 通过后，后续阶段仍可按同一独立工程/ID/配置边界整体弃用，不影响原插件。
